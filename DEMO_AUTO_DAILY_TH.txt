DEMO แบบอัปเดตตามปฏิทินไทยอัตโนมัติ

ทุกสาขาใช้วันที่ไทยวันเดียวกัน แต่ยอดขายและสต็อกของแต่ละสาขายังแยกจากกัน
โหมดปกติไม่ได้สร้างข้อมูลอัตโนมัติตามระบบนี้

วิธีใช้
1. เปิด Backend และ Flutter ตาม RUN_BACKEND_TH.txt
2. เปิด Demo ครั้งแรก แล้วเลือกสาขาที่ต้องการ
3. แถบด้านบนแสดง DEMO | Thailand date YYYY-MM-DD | Auto update
4. ลองสลับทั้ง 4 สาขา วันที่ต้องตรงกัน ไม่ต้องกดปุ่มเดินวันหรือปิดยอดจำลองเอง

สิ่งที่ระบบทำเมื่อเปลี่ยนวันไทย
- ปิดยอดจำลองสำหรับสินค้าในวันก่อนที่ยังไม่มีรายการปิดยอด
- เก็บรายการที่พนักงานปิดไว้แล้วโดยไม่เขียนทับ
- ยกสต็อกแยกล็อต FEFO ไปวันใหม่ และสร้างรายการรับสินค้าจำลองเมื่อไม่พอระดับเป้าหมายทดลอง
- เพิ่มประวัติยอดขาย ของเสีย สต็อก และต้นทุนของเสียที่คำนวณจากล็อต
- สร้างพยากรณ์ใหม่ด้วยโมเดลเดิมและ mock weather หากวันนั้นยังไม่มี run
- ไม่อนุมัติส่วนลดให้ลูกค้าอัตโนมัติ ผู้จัดการยังต้องตรวจและ Approve

เวลาและการเปิดระบบ
Backend ตรวจทุกประมาณ 30 วินาทีโดยใช้เวลาไทย UTC+7 ไม่ใช้วันจากเครื่องลูกค้า
เมื่อแอปเปิดอยู่ใน Demo จะตรวจวันและโหลดข้อมูลวันใหม่ให้เอง
ถ้าปิด Backend ไว้จะไม่มีโปรแกรมทำงานตอนเที่ยงคืน แต่เมื่อเปิดใหม่จะตามวันที่ขาดให้
หากเปิดแท็บไว้เบื้องหลัง Browser อาจลดความถี่ Timer จึงอาจอัปเดตช้ากว่า 30 วินาที
ไม่ต้องพิมพ์คำสั่งเพิ่มในแต่ละวัน แต่ต้องเปิด Backend เมื่อต้องการใช้เว็บ

ข้อมูลทั้งหมดที่ระบบสร้างเป็นข้อมูลทดลอง ไม่ใช่ยอดขายจริง
ประวัติปิดยอดที่สร้างใหม่ระบุ source DEMO_CALENDAR_SIMULATED_CLOSE
ล็อตรับอัตโนมัติใช้ชื่อ AUTO-... และ source DEMO_CALENDAR_RECEIPT
รายการพยากรณ์อัตโนมัติใช้อากาศ mock อย่างชัดเจน หากต้องการอากาศจริงให้เลือก OpenWeather live แล้ว Run
ใช้ History เพื่อดูวันก่อน และ Inventory เพื่อดูวันปัจจุบัน

ระบบไม่ย้อนวันหรือลบข้อมูลอนาคตที่เคยทดลองไว้ ถ้ามีสาขาเดินเลยวันไทยจริง ระบบจะแจ้งข้อขัดแย้งให้ตรวจ
ก่อนเริ่มตามวันครั้งแรกมีสำเนาฐานข้อมูลท้าย .pre_calendar.sqlite
ประวัติ replay เก่าที่ชนกับวันที่ยังไม่ปิดจะถูกเก็บใน demo_calendar_archived_history ก่อนแทนด้วยยอดจำลองที่สมดุล
